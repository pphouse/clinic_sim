# 仕様：シミュレーション核

## 刻みは 1 ヶ月

保険診療は月で回る。レセプトは翌月10日提出・翌々月入金、決算は月次、外来患者数は月報。
四半期という単位は病院の現場語彙ではないので、シムの刻みも1ヶ月に置く。

**ただし検証モデル（med_sim2.xlsx）は四半期で作られている。**
だから定数は「四半期で検証した値を月に割ったもの」であって、勝手に置いた値ではない。
割り方は2種類あり、**混ぜてはいけない**：

| 種類 | 割り方 | 例 |
|---|---|---|
| フロー量（金額・人数・日数） | 3 で割る | 診察日数 60日/四半期 → 20日/月 |
| 率（離脱・離職・評判の回帰・金利） | 複利で割る `1-(1-r)^(1/3)` | 離脱 4%/四半期 → 1.3515%/月 |

率を単純に3で割ると3ヶ月後に元より多く減る。`monthlyFromQuarterly()` を必ず通す。

## 因果の鎖

```
診察枠 = 医師数 × 32人/日 × 20日
実効枠 = 診察枠 × 看護師充足率
     ↓
稼働率 = 診察需要 / 実効枠
     ↓
待ち時間 = 15分 × MAX(1, 稼働率)^2.5          ← 無次元なので刻みを変えても同じ式
     ↓
  ├→ 評判(t) = 評判(t-1) + (75 - 評判(t-1))×5.273% − 超過分×0.2
  │        ↓
  │      新規患者(t) = ポテンシャル × 評判(t-3)/75   ← 遅延の源泉①：3ヶ月前の評判
  │
  └→ 離脱率 = 1-(1-(4% + 超過分×0.25%))^(1/3)
           ↓
        患者ストック(t) = 前月×(1-離脱率) + 新規
           ↓
        収益 = MIN(需要, 実効枠) × 750点 × 10円 × 実効点数指数/100
```

超過分 = MAX(0, 待ち時間 − 20分)

## 遅延は 2 箇所で作られている。消してはいけない

1. **新規患者が「3ヶ月前の」評判に依存する**
2. **評判の回帰が遅い**（月あたり 5.273%＝四半期 15% と同じ速さ。時定数 約 18ヶ月）

この 2 つの合成で、待ち時間の悪化が患者ストックの減少として現れるまでに
**約1年**かかる。検証済みの値であり、テストで固定している。

★1 を「前月の評判」にすると遅延が 1/3 に縮み、検証済みの手触りが壊れる。
月刻みにしても **3ヶ月のラグは保つ**（`NEW_PATIENT_REPUTATION_LAG_MONTHS`）。

短くすると単なる作業ゲームになり、長くすると理不尽になる。**触るなら意図的に。**

## 検証済みの挙動（回帰防止テストの対象）

既定シナリオ：A院で 13〜24ヶ月目に常勤医が 3 → 2 名に減る。

| | 値 |
|---|---|
| 待ち時間のピーク | 19ヶ月目 / 71.3 分 |
| 患者ストックの底 | 32〜38ヶ月目（平坦な谷） |
| 遅延 | ピークから谷の入口まで 13 ヶ月 |
| 評判の最低値 | 40.5（12ヶ月目は 75） |
| 72ヶ月目の患者ストック | 12ヶ月目の水準に**まだ戻っていない** |

**壊すのは一瞬、直すのは何年。** これがこのゲームの手触りの中心。

### 四半期モデルとの差（月刻みにして見えるようになったもの）

待ち時間のピークが 53.2分 → 71.3分 に跳ね上がっている。**これはズレではない。**

19ヶ月目は B院の開院月で、全社の必要看護師数が 5.0 → 7.5 に一段跳ね上がる。
看護師は月に 0.4 人しか採れないので、**開院した月は A院の看護師が一気に薄まる。**
四半期モデルは1四半期に1度しか状態を見ないため、この1ヶ月の谷を均していた。

分院を開けた瞬間に本院が詰まる、というのは現場で実際に起きることなので、
見えるようになったこと自体は正しい。四半期に足し上げれば検証データと 2.5% 以内で一致する
（`test/golden.test.ts`）。

## 捌けなかった需要は消える

```
実施診察数 = MIN(需要, 実効枠)
```

溢れた分は収益にならず、待ち時間として跳ね返るだけ。翌月に繰り越さない。
医師を増やすタイミングを逃すと、その月の売上は永久に失われる。

## 加算が主戦場

検証で判明したこと：**改定の衝撃より加算の方が大きい。**

- 改定#3（−5%）からの営業利益の回復に要した期間：**1〜3 ヶ月**
- 加算 5 つ揃うと点数が **+19%** 乗る

つまり基礎点数の増減は誤差に埋もれる。加算の**取得・維持・失効**を厚くする。
要件（医師数・看護師充足率）を割ると自動的に落ちるのが緊張の源。
月刻みにすると要件割れが月単位で判定されるので、四半期モデルより機微になった。

## 人材の調達

医師と看護師は詰まり方が違う。ここを混ぜると設計が崩れる。

### 医師 — 枠の問題

```
調達可能数 = 医局の派遣枠 + 紹介会社の確保枠（累計）
派遣枠     = FLOOR(医局関係値 / 20)
```

医局関係値は 0〜120。**金では買えない。** 維持費（40万/月）を払っている間は
据え置き、払わなければ 0.667pt/月で落ちる。上げるのは当直の引き受けなど非金銭的な貢献。

紹介会社は 1 枠 500 万。払った月に枠が増え、以後ずっと残る。
配置したい医師数が調達可能数を超えると `doctorShortfall` が立つ。

### 看護師 — 流量の問題

全社プールで持ち、各院へは医師数で按分する。

```
在籍(t) = MIN(必要数, 在籍(t-1)×(1-1.6952%) + 卒業生 + 市場採用)
必要数  = 常勤医数 × 2.5
市場採用 = MIN(0.4, 不足分)          ← 全社合計。ここが最大のボトルネック
充足率  = MIN(1, 在籍 / 必要数)
```

必要数を超えては抱えない。医師が減った月に在籍が必要数まで落ちるのはこのため。

★月に 0.4 人しか採れないので、**分院を開けた月は必ず充足率が落ちる。**
必要数は開院と同時に跳ねるのに、採用は追いつかない。これが月刻みの主戦場になった。

看護学校は開校の 3 年後（36ヶ月後）から、毎年 1 学年ぶんが**まとめて**卒業する。
残るのは `40人 × 卒業率85% × 定着率35% = 11.9 人`。市場採用のおよそ 30 ヶ月分にあたる。
学費は在学中の学年数ぶん立つので、開校から 3 年かけて 200 → 400 → 600 万/月に増える。

## 加算の取得・維持・失効

```
実効点数指数 = 点数指数 × (1 + 有効な加算の合計率)
```

- 取得はその月から効く
- 施設基準（常勤医数・看護師充足率）は **全社** で判定する
- 要件を割った月に **即座に落ちる。猶予期間は無い**
- 要件を満たし直せば戻る。ただし落ちていた間の点数は戻らない

「取得したが一度も要件を満たしていない」加算は、まだ何も失っていない。
`lapsedByRequirement` は素直に「取得済みだが要件割れ」を表すので、
**落ちていた期間**を数えるときは `addonLapseMonths()` を使う。
月単位で判定されるので、四半期モデルより落ちやすい。

## 1 ヶ月の順番

入れ替えると検証済みの結果が変わる。

1. 意思決定を適用する（医師配置・開院・開校・加算取得・紹介会社・医局）
2. 人材を確定する（看護師の増減 → 充足率）
3. 診療報酬を確定する（改定の累積 × 有効な加算）
4. 各院を tick する
5. 三表を組む

3 が 2 の後にあるのは、加算の施設基準が**その月の**充足率で判定されるため。

## やらないこと

- **改定の予測ゲーム化。** 検証で没になった。改定は起きた後に適応する外部イベント
- **Math.random()。** 乱数は createRng(seed) からのみ
- **Date の使用。** 時刻は月インデックス（1〜120）のみ
- **先回りの警告。** 「このままだと1年後に患者が減ります」は出さない。
  遅延はこのゲームの設計そのものなので、先回りすると手触りが消える
