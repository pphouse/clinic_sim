# 仕様：シミュレーション核

## 因果の鎖

```
診察枠 = 医師数 × 32人/日 × 60日
実効枠 = 診察枠 × 看護師充足率
     ↓
稼働率 = 診察需要 / 実効枠
     ↓
待ち時間 = 15分 × MAX(1, 稼働率)^2.5
     ↓
  ├→ 評判(t) = 評判(t-1) + (75 - 評判(t-1))×0.15 − 超過分×0.6
  │        ↓
  │      新規患者(t+1) = ポテンシャル × 評判(t)/75     ← 遅延の源泉①
  │
  └→ 離脱率 = 4% + 超過分×0.25%
           ↓
        患者ストック(t) = 前期×(1-離脱率) + 新規
           ↓
        収益 = MIN(需要, 実効枠) × 750点 × 10円 × 実効点数指数/100
```

超過分 = MAX(0, 待ち時間 − 20分)

## 遅延は 2 箇所で作られている。消してはいけない

1. **新規患者が「前四半期の」評判に依存する**（1Q の遅れ）
2. **評判の回帰率が 0.15/Q と遅い**（時定数 約 6Q）

この 2 つの合成で、待ち時間の悪化が患者ストックの減少として現れるまでに
**4 四半期**かかる。検証済みの値であり、ゴールデンテストで固定している。

短くすると単なる作業ゲームになり、長くすると理不尽になる。**触るなら意図的に。**

## 検証済みの挙動（回帰防止テストの対象）

既定シナリオ：A院で Q5〜Q8 に常勤医が 3 → 2 名に減る。

| | 値 |
|---|---|
| 待ち時間のピーク | Q7 / 53.2 分 |
| 患者ストックの底 | Q11 |
| 遅延 | 4 四半期 |
| 評判の最低値 | 41.4（Q4 時点は 75） |
| Q24 時点の患者ストック | Q4 の水準に**まだ戻っていない** |

**壊すのは一瞬、直すのは何年。** これがこのゲームの手触りの中心。

## 捌けなかった需要は消える

```
実施診察数 = MIN(需要, 実効枠)
```

溢れた分は収益にならず、待ち時間として跳ね返るだけ。翌期に繰り越さない。
医師を増やすタイミングを逃すと、その四半期の売上は永久に失われる。

## 加算が主戦場

検証で判明したこと：**改定の衝撃より加算の方が大きい。**

- 改定#3（−5%）からの営業利益の回復に要した期間：**0〜1 四半期**
- 加算 5 つ揃うと点数が **+19%** 乗る

つまり基礎点数の増減は誤差に埋もれる。加算の**取得・維持・失効**を厚くする。
要件（医師数・看護師充足率）を割ると自動的に落ちるのが緊張の源。
既定シナリオでは 8 四半期にわたって加算が要件割れで失効していた。

## 人材の調達

医師と看護師は詰まり方が違う。ここを混ぜると設計が崩れる。

### 医師 — 枠の問題

```
調達可能数 = 医局の派遣枠 + 紹介会社の確保枠（累計）
派遣枠     = FLOOR(医局関係値 / 20)
```

医局関係値は 0〜120。**金では買えない。** 維持費（120万/四半期）を払っている間は
据え置き、払わなければ 2pt/四半期で落ちる。上げるのは当直の引き受けなど非金銭的な貢献。

紹介会社は 1 枠 500 万。払った四半期に枠が増え、以後ずっと残る。
配置したい医師数が調達可能数を超えると `doctorShortfall` が立つ。

### 看護師 — 流量の問題

全社プールで持ち、各院へは医師数で按分する。

```
在籍(t) = MIN(必要数, 在籍(t-1)×(1-5%) + 卒業生 + 市場採用)
必要数  = 常勤医数 × 2.5
市場採用 = MIN(1.2, 不足分)          ← 全社合計。ここが最大のボトルネック
充足率  = MIN(1, 在籍 / 必要数)
```

必要数を超えては抱えない。医師が減った四半期に在籍が必要数まで落ちるのはこのため。

看護学校は開校の 3 年後（12四半期後）から、毎年 1 学年ぶんが卒業する。
残るのは `40人 × 卒業率85% × 定着率35% = 11.9 人`。市場採用のおよそ 10 四半期分にあたる。
学費は在学中の学年数ぶん立つので、開校から 3 年かけて 600 → 1,200 → 1,800 万/四半期に増える。

## 加算の取得・維持・失効

```
実効点数指数 = 点数指数 × (1 + 有効な加算の合計率)
```

- 取得はその四半期から効く
- 施設基準（常勤医数・看護師充足率）は **全社** で判定する
- 要件を割った四半期に **即座に落ちる。猶予期間は無い**
- 要件を満たし直せば戻る。ただし落ちていた間の点数は戻らない

「取得したが一度も要件を満たしていない」加算は、まだ何も失っていない。
`lapsedByRequirement` は素直に「取得済みだが要件割れ」を表すので、
**落ちていた期間**を数えるときは `addonLapseQuarters()` を使う。
既定シナリオでは 8 四半期（Q5,6,7,9,10,15,31,32）。

## 1 四半期の順番

入れ替えると検証済みの結果が変わる。

1. 意思決定を適用する（医師配置・開院・開校・加算取得・紹介会社・医局）
2. 人材を確定する（看護師の増減 → 充足率）
3. 診療報酬を確定する（改定の累積 × 有効な加算）
4. 各院を tick する
5. 三表を組む

3 が 2 の後にあるのは、加算の施設基準が**その四半期の**充足率で判定されるため。
既定シナリオでは Q9・Q15 がこれで落ちる。

## やらないこと

- **改定の予測ゲーム化。** 検証で没になった。改定は起きた後に適応する外部イベント
- **Math.random()。** 乱数は createRng(seed) からのみ
- **Date の使用。** 時刻は四半期インデックスのみ
- **先回りの警告。** 「このままだと4四半期後に患者が減ります」は出さない。
  遅延はこのゲームの設計そのものなので、先回りすると手触りが消える
