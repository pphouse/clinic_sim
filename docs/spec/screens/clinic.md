# 画面仕様：診療所

> ステータス: **プロトタイプ実装済み（手触り確認用）**
> 担当ブランチ: `feature/screen-clinic`
> ScreenId: `clinic`
> 領域色: `hq`

## この画面の唯一の仕事

1院の詳細。**診察枠 → 待ち時間 → 評判・離脱 → 患者ストック → 収益** の因果の鎖が、
1画面の中で順番に読めること。★中核ループが見える画面。

## 表示するデータ

sim から読む値だけを列挙する。UI で計算しない（CLAUDE.md §2）。

### ヒーロー行（タブに関係なく常に出す）

| 表示名 | sim のフィールド | 書式 |
|---|---|---|
| 通院患者 | `ClinicTick.patientStock` | 人・整数＋**前月比** |
| 待ち時間 | `ClinicTick.waitMinutes` | 分・小数1桁＋**前月比** |
| 評判 | `reputationStars(reputation)` | **星5段階**＋小数1桁＋前月比 |

前月比は `clinicDelta()` から読む。増減が無いと、月を送っても何が動いたか分からない。
0 のときは `+0` ではなく `±0` と出す。`+0` は動いたように見える。

### 推移（ヒーロー行の直下）

**直近24ヶ月の「通院患者」と「待ち時間」を2本の折れ線で重ねる。**

★この画面でグラフが要る理由は見栄えではない。このゲームの主題は遅延で、
待ち時間の山と患者ストックの谷は**1年ずれている**。
並べて描かないと、そのズレは絶対に伝わらない。数字を月送りで見せても因果は結べない。

- 24ヶ月なのは、遅延が1年なので山と谷が両方入る長さが要るため
- 縦軸は系列ごとに独立に正規化する。分と人を同じ軸には載せられないし、
  見せたいのは水準ではなく**山と谷の位置**だから
- 最新の点だけ丸で強調する。「いまここ」が線上のどこか迷わせない
- 開院前の月は線に含めない（0から立ち上がると誤読する）

## プレイヤーができること

| 操作 | 効果 | 反映されるまでの遅延 |
|---|---|---|
| 月を進める / 戻す（1ヶ月・1年） | 表示中の月が変わる | 即時（表示のみ） |
| その月の常勤医を増減する | 意思決定の列を書き換えて全期間を再計算する | 待ち時間は**即時**、評判は緩慢、患者ストックは**約1年後** |

医師の増減は「その月以降」に効く。`BASELINE_SCENARIO` の意思決定リストを
書き換えて `runSimulation()` を回し直すだけで、未来が全部組み替わる。
**シム核は純粋関数なので、これで正しい。** UI 側で差分計算をしない。

> **プロトタイプの制約：** 現状は全120ヶ月を一括で回して結果を読んでいる。
> 「月ごとに意思決定を確定して進める」逐次 API（`stepMonth`）はまだ無い。
> セーブデータを入れるときに必要になるので、そのとき sim 側へ足す。

### 評判を星で出す理由

評判は 20〜100 の数値だが、**41.4 が悪いと分かるまでに一拍かかる。**
評判はプレイヤーが直接いじれない結果なので、精度より体感を優先して星で出す。

`REPUTATION_MIN=20` がちょうど星1、100 が星5になる。口コミサイトに星0が無く
下限が星1なのと同じ形になり、「最低でも1つは付いている」手触りが実物と揃う。

端数は星を横に切って出す。**丸めない。** 評判は月に数%しか動かないので、
丸めると「1ヶ月では何も変わらない」ように見えてしまう。数値の併記も同じ理由。

## NPC の挨拶文

状況に応じて出し分ける。「こんにちは院長」ではなく、
**今この画面で見るべきものを名指しする。**

| 条件 | 文言 |
|---|---|
| 通常（待ち時間 ≤ 20分） | 「待ち時間は{n}分。いまのところ枠は足りています」 |
| 警告（20分 超） | 「待ち時間が{n}分です。許容の20分を超えました。評判が削られ始めています」 |
| 危機（45分 以上） | 「待ち時間{n}分。もう評判は落ちています。患者が減り始めるのは1年ほどあとです」 |
| 評判が下限 | 「評判が下限です。ここから戻すのに何年かかるか、ご承知おきください」 |

## 通知バッジを出す条件

`MonthResult.events` のうち `screen === 'clinic'` かつ当該院のものを数える。
`severity` は sim が決める。UI は数えて出すだけ。

## やらないこと

- **予測の表示。** 「このままだと1年後に患者が減ります」は出さない（docs/spec/01-simulation-core.md）
- **UI での計算。** 引き算ひとつでも sim 側に derive を足す
- **横スクロールする表。** 列が足りないならタブで割る（CLAUDE.md §5）
- **他院との比較。** それはマップ画面の仕事
