# 画面仕様：月次ダイジェスト

「翌月へ」を押した直後に出る**全画面の差し替え**。数秒で消える。

## この画面の唯一の仕事

**1ヶ月進めたことに手応えを与える。**

それまでは「翌月へ」を押しても、マップの数字が静かに書き変わるだけだった。
月を10回進めても、何が起きたのか一度も分からないまま10ヶ月が過ぎる。
このゲームの主題は**遅延**なので、押した結果が見えないことは致命的に相性が悪い。
「3ヶ月前に医師を1人減らしたのが、いま患者数の減少として出てきた」を
気づかせる場所がどこにも無かった。

だからこの画面は**変化しか出さない。** 絶対値は主役ではない。

## 出るタイミング

| 条件 | 挙動 |
|---|---|
| 「翌月へ」を押した | 進んだ先の月のダイジェストを出す |
| 過去へ戻る / 進む | 出さない（月は確定していない。見る場所が変わっただけ） |
| 1ヶ月目（ゲーム開始時） | 出さない（前月が無い） |
| 終局した月 | 出さない（終局画面が出る。2枚重ねない） |

## 表示するデータ（`monthDigest(current, previous)`）

sim が行を組み立てる。**UI は並べて動かすだけで、何を出すかを決めない**（CLAUDE.md §2）。

| 行 | sim のフィールド | 単位 | 増えると良いか |
|---|---|---|---|
| 通院患者 | `totalPatientStock` | 人 | ○ |
| 営業利益 | `deriveGroupTotals().operatingIncome` | 万円 | ○ |
| 現金 | `balanceSheet.cash` | 万円 | ○ |
| 待ち時間 | `worstWait().waitMinutes` | 分 | ✕ |
| 評判 | `groupReputation` | 星 | ○ |

**増減の善し悪しを決めるのは sim**（`higherIsBetter`）。
待ち時間だけ向きが逆なので、UI 側に「待ち時間は増えたら赤」と書くと
別の画面で必ず忘れる。

### 見出し（`headline`）

**いちばん大きく動いた行**から一言を作る。動きが小さければ「変化なし」。
何を大きいとするかは比率で見る（現金 100万 と 患者 100人 は比べられない）。

### 出来事（`events`）

その月に起きた `GameEvent` をそのまま並べる。突発事象・開院・加算の取得・
債務超過の警告が全部ここに出る。**これまで通知はマップのバッジにしか出ておらず、
月を進める勢いで踏み潰されていた。**

## アニメーション

| 要素 | 動き | 長さ |
|---|---|---|
| 背景 | 暗転してフェードイン | 180ms |
| 月表示 | 上からスライドイン | 260ms |
| 各行 | 下から順に立ち上がる（80ms ずつずらす） | 各 300ms |
| 数字 | 前月の値から今月の値へ数え上げる | 520ms |
| 増減バッジ | 数え上げが終わってから遅れて出る | 200ms |

**数え上げは前月の値から始める。** 0 から始めると
「増えた」と「そもそも大きい」の区別がつかない。

`prefers-reduced-motion` のときは全部止めて、最終値をそのまま出す。

## プレイヤーができること

| 操作 | 効果 |
|---|---|
| どこかをタップ | すぐ閉じる |
| 何もしない | 出来事が無ければ自動で閉じる |

**出来事があるときは自動で閉じない。** 読ませたいから出している。

## やらないこと

- **意思決定を置かない。** ここは結果を見る場所。決めるのは各画面
- **未来を見せない**（CLAUDE.md §7）。出すのは進んだ先の月まで
- **UI で差分を計算しない。** `monthDigest` が全部持ってくる
