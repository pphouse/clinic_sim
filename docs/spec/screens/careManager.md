# 画面仕様：ケアマネ・地域包括

> ステータス: **実装済み**
> ScreenId: `careManager`
> 領域色: `hospital`（青緑。連携基幹病院と同系）

領域色を基幹病院と揃えてあるのは意図的。**どちらも「外から患者を回してもらう」
系統**で、プレイヤーの頭の中では同じ引き出しに入る。色を分けると別物に見える。

## この画面の唯一の仕事

在宅医療の紹介を受ける。**単価は上がるが、訪問に出る分だけ診察枠が減る。**

## 判断の中身

```
在宅比率 ↑ → 自費単価 ↑（在宅は 1.2 倍）
           → 診察枠 ↓（訪問に出ている間、外来を診られない）
```

外来が空いているうちは在宅が効く。外来が詰まっている（稼働率 > 1）ときに
在宅を増やすと、待ち時間が伸びて評判が落ちる。**同じ操作が状況で逆に働く。**

## 表示するデータ

| 表示名 | sim のフィールド | 書式 |
|---|---|---|
| 関係値 | `expansion.relations.relations[careManager].value` | 0〜100 |
| 在宅比率 | `expansion.relations.homeCareShare` | % |
| 自費の上乗せ | `expansion.selfPayMultiplier` | +% |
| 枠への影響 | `expansion.capacityMultiplier` | % |
| 全社の稼働率 | `clinics[].utilization` の最大 | % |

最後の行が判断に要る。**稼働率が 1 を超えているなら在宅を増やしてはいけない。**

## プレイヤーができること

| 操作 | 効果 | 反映されるまでの遅延 |
|---|---|---|
| 営業を続ける／やめる | 続けると +1.4/月、やめると −0.5/月 | 比率は即時、評判への跳ね返りは3ヶ月〜1年 |


## NPC の挨拶文

| 条件 | 文言 |
|---|---|
| 通常 | 「訪問をお願いできる先生を探していまして」 |
| 外来が詰まっている | 「外来が ◯分待ちだそうですね。訪問まで手が回りますか」 |
| 関係が切れている | 「最近は別の先生にお願いしています」 |

2行目が効く。**NPC がプレイヤーの他画面の数字を見て止めに来る。**

## 通知バッジを出す条件

- 在宅比率が上がっている最中に、待ち時間が許容を超えた（warning）

## やらないこと

- 介護報酬を別系統でモデル化する。自費単価の係数1本に畳む
- 訪問件数を個別に管理する。粒度が細かすぎてモバイルに載らない
