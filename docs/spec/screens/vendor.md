# 画面仕様：システム・機器商社

> ステータス: **未着手**
> 担当ブランチ: `feature/screen-vendor`
> ScreenId: `vendor`
> 領域色: `vendor`（鋼青 / steel）

## この画面の唯一の仕事

設備・システムへの投資を決める。**3つとも「今の現金を削って、将来の診察枠か点数を買う」**
という同じ形の判断なので、建物を分けずに1画面3タブにまとめる。

## タブ構成

```
[医療機器] [電子カルテ] [AI]
```

---

# タブ1：医療機器

## 判断の中身

購入かリースか。**B/Sがあるから成立する判断。**

| | 購入 | リース |
|---|---|---|
| B/S | 固定資産に計上 | 載らない |
| P/L | 5年で減価償却 | 月額を全額費用 |
| キャッシュ | 一括で重い | 平準化 |
| 総支払額 | 基準 | +15% |
| 加算の施設基準 | 満たす | 満たす |

序盤は現金が無いのでリース一択になる。だが固定費が積み上がり、黒字化が遠のく。
**目先の資金繰りと総コストのトレードオフ。**

## 保守契約

| | 年額 | 故障時 |
|---|---|---|
| 加入 | 機器価格の 8% | 即日復旧 |
| 非加入 | 0 | 該当機器を要件とする加算が失効、修理まで 1〜2 四半期 |

保守を切るのは合理的に見えるが、故障は加算の要件割れを引き起こす。
検証では加算1つの失効が数千万円規模で効いていた。

## 表示するデータ

| 表示名 | sim のフィールド | 書式 |
|---|---|---|
| 保有機器 | `state.assets`（assetClass = medicalEquipment） | 一覧 |
| 簿価 | `FixedAsset.bookValue` | 万円 |
| 残存耐用 | `usefulLifeQuarters - 経過` | 四半期 |
| リース料合計 | `incomeStatement.leaseExpense` | 万円/四半期 |

# タブ2：電子カルテ ★この画面の主役

## なぜ主役か

**カルテ移行は、プレイヤーが自分で起こす医師不足。**

```
移行実行 → 診察枠が 2 四半期 −20%
  → 待ち時間↑ → 評判↓ → 4 四半期後に患者ストック↓
```

検証済みの「医師1名欠員」と全く同じ経路を通る。違うのは**自分で選ぶ災害**であること。

## ティア

| | 初期費用 | 月額 | 多施設統合 | DX推進加算 | 移行時の枠低下 |
|---|---|---|---|---|---|
| 単院向け | 300万 | 15万 | ✗ | ✗ | — |
| チェーン対応 | 1,500万 | 60万 | ○ | ○ | −20% × 2Q |
| 大手統合 | 4,000万 | 150万 | ○ | ○ | −25% × 3Q |

## ロックイン

**移行コストはデータ量に比例する。** 遅らせるほど高くつく。

```
移行費用 = 基本費用 × (1 + 累計患者データ量 / 基準量)
```

序盤に安物を選ぶと、中盤で身動きが取れなくなる。だが分院を増やすなら
いつかは乗り換えざるを得ない（単院向けでは法人統合ができない）。
**「いつ痛みを受け入れるか」という決断。**

## 表示するデータ

| 表示名 | sim のフィールド | 書式 |
|---|---|---|
| 現在のティア | `state.emrTier` | ラベル |
| 移行した場合の費用 | `deriveEmrMigrationCost(state)` | 万円 |
| 移行した場合の枠低下 | ティア定義 | % × 四半期 |
| 移行を1年遅らせた場合の費用 | 同上（患者数の予測込み） | 万円 |

最後の行が重要。**待つことのコストを明示する。**

# タブ3：AI

## 設計上の注意

**3タブの中で一番「それっぽいだけ」になりやすい。**
「AI導入で効率化」と書いてあるだけで何の判断もない画面になりがち。

これを避ける設計が1つだけある：**キャパシティと施設基準を切り離す。**

| | 効果 | 施設基準の医師数にカウント |
|---|---|---|
| 常勤医 1名 | +32 人/日 | **○** |
| 問診AI | +3 人/日 | ✗ |
| 画像診断AI | +4 人/日 | ✗ |

AIは医師を雇うより安く回転を上げられる。**だが加算は取れない。**
検証で「主戦場は加算」と分かっている以上、この非対称が判断を生む。

「安く捌けるようになったのに、点数は上がらない」という歪みを体験させる。

## やらないこと

- AIの精度・誤診をリスクイベントにするのは**保留**。題材として扱いが難しく、
  ゲーム的な必然性も薄い。まず上の非対称だけで面白くなるか確かめる
- AI事業者を別の建物にする（画面が増えすぎる）

---

## NPC の挨拶文

| 条件 | 文言 |
|---|---|
| 通常 | 「新しい機種のカタログをお持ちしました」 |
| 移行を先送りしている | 「カルテの移行、今年やるなら◯◯万円です。来年だと◯◯万円になります」 |
| 保守未加入で故障 | 「保守に入っていないので、部品の取り寄せに2ヶ月かかります」 |

2行目が効く。**待つことのコストを、NPCの口から言わせる。**

## 通知バッジを出す条件

- 保守契約の切れる機器がある（warning）
- 機器の故障で加算が失効した（critical）
- 分院追加により現行カルテのライセンス上限に達した（warning）
