# 判断の密度

★**この層は検証されていない。** 既定シナリオは `features` が全てオフなので、
ここに書いた仕組みは1度も走らない。`baseline.golden.json` は動かない。

---

## 1. なぜ作るか

プレイテストで出た指摘：**「そんなゲームでおもろい？」**

そのとおりだった。数えてみると、**120ヶ月のうち判断がある月が10回もない。**
開業で3回、医師の増減で数回、集患で数回、分院で2〜3回。
残りの110回は「翌月へ」を押して数字が動くのを見ているだけ。

そこへ集患と破綻を足したのは、**退屈な部分を長く・重くしただけ**だった。
「簡単すぎる」の正体は簡単さではなく、**やることが無いこと**。

だからここで足すのは難易度ではなく、**判断の回数**と**押す回数の圧縮**。

## 2. イベントを「知らせる」から「訊く」に変える

突発事象はこれまで、起きたことを報告するだけだった。選択肢を持たせる。

| イベント | 選ぶ | 既定（何もしない） |
|---|---|---|
| 常勤医が辞めたいと言っている | 引き止める（700万） | 辞める＝枠が落ちる |
| 看護師がまとめて辞めそう | 待遇で引き止める（400万） | 2名抜ける |
| 口コミサイトに悪い書き込み | 体制を見直す（150万） | 評判 −8 |
| 近隣に大きなマンションが建つ | 待合と駐車場を広げる（1,200万） | 何も起きない |
| 医師会から役員の打診 | 引き受ける（300万） | 関係値 −5 |

競合の開業・個別指導・感染症の流行は**知らせるだけのまま**。
相手の都合で起きることに選択肢を付けると嘘になる。

### 効果の語彙は閉じている

選択肢が動かせるのは6つだけ。**新しい因果を発明しない**（randomEvents.ts の方針）。

```
cost                 即時の現金支出（特別損失）
keepDoctor           医師が抜けるのを止める
keepNurses           看護師の離職を止める
reputationDelta      その院の評判への即時の増減
potentialMultiplier  その院の新規患者ポテンシャルへの恒久倍率
relationDelta        外部関係値の増減
```

どれも既にある状態変数で、既に検証済みの経路（評判 → シェア／3ヶ月後の新規患者、
枠 → 待ち時間）に流し込むだけ。

### ★答えは「意思決定」として保存する

セーブは決定列だけを持つ（03-game.md §5）。イベントの答えも決定列に入れる。

```
MonthDecision.eventChoices?: Record<string, string>   // イベントの鍵 → 選択肢のid
```

イベントの鍵は `${id}-${clinicId ?? 'group'}-${month}` で一意にする。

**答えなければ既定の選択肢が適用される。** だから：

- 放置しても盤面は進む（詰まらない）
- 答えを記録して回し直すと、同じ乱数列で同じイベントが出て、今度は答えが効く
- セーブに状態を持たせずに済む

## 3. 序盤に小さい達成を置く

最初の3年は赤字を見続けるだけで、何も起きない。節目を通知として出す。

| 節目 | 条件 |
|---|---|
| 初めての黒字 | 経常利益が初めてプラスになった月 |
| 通院患者 1,000人 | 全社の患者ストックが初めて 1,000 を超えた |
| 2院目 | 2つ目の院が開いた |
| 借入が半分 | 借入残高が最大時の半分を切った |

**数字は何も動かさない。** 節目は通知であって効果ではない。

`features.milestones` がオンのときだけ出す。既定シナリオはオフ。

## 4. やらないこと

- **選択肢に「正解」を作らない。** どちらにも取り返しのつかない代償がある
- **イベントで直接患者を増減しない。** 必ず既存の経路（評判・枠・ポテンシャル）を通す
- **節目に報酬を付けない。** 付けると節目を狙う遊びになり、経営の判断が歪む
- **月をまとめて飛ばさない。** 一度「判断まで進む」を作ったが外した（下記）

### 空の月を飛ばす仕組みを外した理由

次に手が要る月まで一気に進めるボタンを置いていた。実測で120回の月送りが7回になった。
**押す回数は確かに減ったが、減らす方向が間違っていた。**

このゲームの主題は遅延で、遅延は**待つ月を数えて初めて痛みになる**。
まとめて飛ばすと、医師を増やしてから患者が動くまでの3ヶ月が1回の画面遷移に潰れ、
「効くのが遅い」という手応えそのものが消える。
退屈なのは月送りの回数ではなく判断の少なさで、それは §2 と §3 で埋める話。

月は1つずつ進める。ダイジェストは常に1ヶ月ぶん（`monthDigest`）。
