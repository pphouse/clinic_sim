# 診療科

検証モデルは科を持っていなかった。1本の「診療所」があるだけで、
通院頻度も単価も1日に診られる数も全部ひとつの値だった。

この文書はその上に載る**遊びの層**。数値は検証されていない。

---

## 1. ★科を選ぶ楽しさはどこから来るか

科ごとのステータスを並べるだけでは、強い科と弱い科ができて終わる。
面白くなるのは**市場のセグメントが（商圏 × 科）になる**からで、ここが要。

```
本町内科クリニック（強さ70）が居る本町に、
  内科で出す   → 真っ向勝負。シェアを取り合う
  皮膚科で出す → **相手が居ない。** シェア100%
```

**内科の隣に皮膚科を出しても患者を食い合わない。** 実際そうだし、
これがあるだけで「どこにどの科を出すか」が読み合いになる。

同じ理由で、自院同士の食い合いも科が同じときだけ起きる。
本町に A院（内科）と D院（皮膚科）なら、互いに無関係。

## 2. 内科は恒等

**内科の値は検証済みの定数そのもの。** 倍率ではなく実数で書いてある。

```ts
{ id: 'naika', visitsPerPatientPerMonth: VISITS_PER_PATIENT_PER_MONTH, ... }
```

既定シナリオの A・B・C は全て内科なので、科を足しても数字は 1 ミリも動かない。
他の5科は内科からの差分としてしか意味を持たない。

## 3. 科ごとに変わるもの

材料は**全て既に検証済みの変数**。新しい状態変数は増やしていない。

| | 通院頻度 | 単価 | 枠/日 | 自費 | 離脱 | 設備 | 医師 |
|---|---|---|---|---|---|---|---|
| 内科 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 | 1.0 | 1.0 |
| 小児科 | 1.60 | 0.75 | 1.40 | 0.60 | 1.60 | 0.9 | 1.3 |
| 整形外科 | 1.80 | 0.95 | 1.10 | 0.80 | 1.20 | 1.6 | 1.0 |
| 皮膚科 | 0.70 | 0.70 | 1.60 | 3.00 | 1.50 | 1.1 | 1.1 |
| 眼科 | 0.80 | 1.35 | 1.15 | 1.50 | 1.00 | 2.0 | 1.4 |
| 精神科 | 1.10 | 1.80 | 0.55 | 0.50 | 0.50 | 0.5 | 1.6 |

（表は内科を 1.00 とした比。実装は実数で持つ）

読み方：

- **整形外科**は通院頻度が高い（リハビリ）。患者1人あたりの収入は大きいが、
  **医師1人が抱えられる患者数が少ない**。枠を食う科
- **皮膚科**は回転が速く医師1人で多くを抱えられるが、保険の単価が低い。
  **自費（美容）が3倍**で、そこで稼ぐ
- **眼科**は単価が高い（手術）。ただし設備が2倍、医師も採りにくい。**重い科**
- **精神科**は診察が長く1日に55%しか診られない。単価で釣り合わせてある。
  設備は半分で済み、**離脱率が半分**。患者が離れないので、遅いが確実に積み上がる
- **小児科**は単価が安いが、風邪でよく来るし診察が短い。**数で稼ぐ科**。
  ただし離脱が1.6倍で、子どもは成長して卒業していく。子育て世帯の商圏でしか成立しない

## 4. 医師の採りにくさ

調達枠の消費が科ごとに違う。**精神科の医師1名は派遣枠 1.6 を食う。**

```
消費した枠 = 医師数 × doctorScarcity
```

内科は 1.0 なので恒等。医局の関係値を育てる価値が科によって変わる。

## 5. 商圏ごとの需要

```
その科のポテンシャル = 商圏のポテンシャル × 需要係数
```

| | 内科 | 小児科 | 整形外科 | 皮膚科 | 眼科 | 精神科 |
|---|---|---|---|---|---|---|
| 本町（下町・高齢） | 1.0 | 0.6 | 1.4 | 0.8 | 1.3 | 0.7 |
| 駅前（勤め人） | 1.0 | 0.7 | 0.9 | 1.4 | 0.8 | 1.4 |
| 住宅地（子育て） | 1.0 | 1.6 | 1.0 | 1.1 | 0.9 | 0.8 |
| 新興住宅地（若い世帯） | 1.0 | 1.5 | 0.7 | 1.3 | 0.6 | 1.0 |

内科を全商圏 1.0 に固定しているのは、
**商圏のポテンシャルの校正（`04-market.md` §4）を壊さないため。**

## 6. 競合も科を持つ

| 競合 | 商圏 | 科 |
|---|---|---|
| 本町内科クリニック | 本町 | 内科 |
| 駅前メディカル | 駅前 | 内科 |
| さくら小児科 | 駅前 | 小児科 |
| にじいろクリニック | 新興住宅地 | 小児科 |

突発事象で開業する競合も科を持つ。★**儲かっているところに来る。**
自院の患者数で重み付けして、育っている（商圏 × 科）へ入ってくる。

一様抽選にすると、**空いたセグメントを見つけて放置するのが最適解になる。**
10年のあいだ誰も来ないニッチは、ニッチではない。

## 7. 開院の画面

候補地を押すと**全画面の開院画面**へ（モーダルは全画面差し替え。CLAUDE.md §5）。
そこで科を選ぶ。並べるのは：

| 表示 | 何のため |
|---|---|
| その商圏でのその科の需要 | 「ここは小児科が強い」が読める |
| そのセグメントに居る競合 | **空いているセグメントが分かる** |
| 医師1人あたりの患者数と単価 | 重い科か軽い科か |
| 設備投資額 | 現金で足りるか |

★**「競合が居ない」を目立たせる。** これがこの画面でいちばん効く情報。

## 8. やらないこと

- 科の転換（開院後に内科→皮膚科）。実務でも簡単ではないし、
  やり直しが効くと立地と科を選ぶ判断が軽くなる
- 複数科の標榜。1院1科にする。**混ぜると科の性格が薄まって、選ぶ意味が消える**
- 科ごとの加算。加算は既に主戦場で、科を掛けると組み合わせが爆発する
- 医師の個人名・専門性の管理。粒度が細かすぎてモバイルに載らない
