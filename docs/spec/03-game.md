# ゲームの層（ゴール・終局・突発事象・進行・セーブ）

シム核（`01-simulation-core.md`）と会計（`02-accounting.md`）は
**検証済みのモデル**を書いたもの。この文書はその上に載る**遊びの層**で、
表計算の裏付けは無い。数値は実際の到達点を測ってから置いた。

---

## 1. 進行 — 未来は見せない

```
currentMonth ── ここまでしか表示しない
    │
    ├── 意思決定を書けるのは currentMonth だけ
    ├── 過去へは戻れる。ただし読むだけ
    └── 「翌月へ」で1ヶ月進む。**戻せない**
```

★かつては120ヶ月を最初に全部計算して自由に行き来していた。やめた理由：

**このゲームの主題は遅延で、未来が見えていると遅延が痛みにならない。**
医師を1名減らした結果が患者ストックに出るのは1年後。
120ヶ月目を見てから13ヶ月目に戻って戻せるなら、そこに判断は無い。

計算は毎回120ヶ月まるごとやり直している（シム核は純粋関数なので差分更新は不要かつ有害）。
**見せる範囲だけを `currentMonth` で切っている。**

終局したあとはタイムラインを開放する。
「あのとき医師を1人減らしたのが31ヶ月目に効いた」を確認するのは、終わってからでいい。

## 2. ゴール — 3本立て。互いに食い合う

| ゴール | 測るもの | 目標 | 伸ばす手 |
|---|---|---|---|
| 資産家 | 個人資産（現金＋見栄資産） | 2.5 億円 | 役員報酬 |
| 規模 | 全社の通院患者 | 11,000 人 | 分院・紹介・加算 |
| 内部留保 | 利益の蓄積（`retainedEarnings`） | 2 億円 | 我慢 |

★**目標値は 06-opening.md §8 で置き直した。**
下の実測表は A院を 3,200人 持って始まっていた頃のもので、
自己資金 1,000万から開業する形になってからの到達点はそちらを見ること。

**3本は同じ財布を取り合う。** 役員報酬を取れば法人が痩せ、
分院を出せば現金が消えて医師会の関係も落ちる。同時に狙うと1本も届かない。

### なぜ純資産ではなく内部留保か

純資産だと開始時の資本金 1.5 億がそのまま乗る。
**「何もしない」が達成率 62% になってしまう。**
測りたいのは10年で何を積んだかであって、最初に持っていた額ではない。

### なぜ目標がこの水準か

検証済みの数式は「拡大するほど儲かる」形をしていない。
枠（医師）を先に買うと、患者が育つ前に人件費で沈む。
実測した到達点：

| 遊び方 | 患者 | 内部留保 | 個人資産 |
|---|---|---|---|
| 何もしない | 2,121 | 611 | 0 |
| 承継1院＋紹介 | 5,489 | 4,380 | 0 |
| 承継＋紹介＋新規1院 | 7,085 | −170 | 0 |
| 役員報酬 500万を後半に | 5,489 | 0 | 8,250 |
| 5院へ急拡大 | — | 42ヶ月目に破綻 | — |

**理想の数字を置くと、どの遊び方でも届かない飾りになる。**
上の実測から、良い経営なら1本は届く水準に置いた。

## 3. 終局

| 条件 | 判定 |
|---|---|
| どれか1本のゴールに到達 | `goal` |
| 120ヶ月が終わる | `timeUp` |
| 債務超過**かつ経常赤字**が **12ヶ月** 続く | `bankrupt` |

破綻の条件は 06-opening.md §7 で2箇所直した。
**最初の開業から36ヶ月は数え始めない**（開業据置）のと、
**黒字で回っているあいだは数えない**（返している最中と潰れているのは違う）。

★**破綻は達成に優先する。** 落ちてからの達成は勝ちにしない。

### 債務超過を1ヶ月で殺さない理由

検証で分かったとおり、看護学校の 2.5 億は費用ではなく校舎という資産で、
あのときの「最低現金 −1.8 億」は**債務超過ではなく資金繰りの谷**だった。
谷で殺すと、正しい大型投資が全部悪手になる。
1年沈みっぱなしなら、それはもう谷ではない。

### 称号

3本の達成率の合計から引く（`ENDING_TITLES`）。破綻したら最下位。

## 4. 突発事象

★**`scenario.features.randomEvents` がオンのときだけ乱数を引く。**
既定シナリオはオフなので、検証済みの120ヶ月は一度も引かない（`game.test.ts` で固定）。

| 事象 | 効き先 | 設計意図 |
|---|---|---|
| 常勤医の退職 | 枠 → 待ち時間 → 評判 → 1年後の患者 | 検証済みの経路をそのまま通る |
| 看護師の同時退職 | 充足率 → 実効枠 | 同上。市場採用は月 0.4 名しか進まない |
| 近隣の競合開業 | 新規患者ポテンシャルが**恒久的に** −15% | 元に戻らない唯一の事象 |
| 厚生局の個別指導 | 特別損失（既に P/L にある行） | **加算を多く持つほど返還が大きい** |
| 感染症の流行 | 需要 +20% を3ヶ月 | 枠が空いていれば増収、詰まっていれば待ち時間 |

**新しい因果を発明しない。** 「イベントが起きたので患者が10%減る」を作ると、
検証したモデルの外側で数字が動いて、何が効いたのか説明できなくなる。

判定の順番は固定。事象を足すときは**必ず末尾に足す**（既存のセーブの再現が壊れる）。

## 5. セーブ

★**保存するのは意思決定の列だけ。状態は保存しない。**

シム核は純粋関数なので、同じ種と同じ決定列からは必ず同じ120ヶ月が出る。
患者ストックも評判も関係値も、決定列から再現できる。

状態を保存すると、式を直したときに古いセーブが
「昔の式で計算された数字」を持ったまま復活して、どちらが正しいのか分からなくなる。

```
{ version, scenarioId, seed, totalMonths, currentMonth, decisions[] }
```

- 版が違うセーブは**読まずに捨てる**
- 壊れていたら `null` を返す。例外を投げるとアプリが起動しなくなる
- 保存に失敗しても落とさない。**保存できないことは遊べない理由にならない**
- `localStorage` を触るのは UI 側だけ（シム核に DOM を持ち込まない）

## 6. 分院

候補地は `CLINIC_SITES`。**承継は患者が付いてくる代わりに高い。**

| id | 立地 | ポテンシャル | 承継患者 | 投資 |
|---|---|---|---|---|
| B | 駅前 | 中 | 0 | 6,000万 |
| C | 住宅地 | 低 | 0 | 6,000万 |
| D | 承継 | 低 | 1,800人 | 11,000万 |
| E | 新興住宅地 | 高 | 0 | 7,000万 |

新規は安いが、評判が育つまで何年も空く。承継は初日から患者がいる。
**どちらが正しいかは手元の現金で決まる。**

`ClinicTick` が `name` / `openMonth` を持つ。
分院はプレイ中に増えるので、**UI が `CLINICS` 定数を読んではいけない**
（読むと「最初から決まっている3院」しか描けない）。

## 7. 借入

純資産の **4倍** が上限。債務超過なら1円も引けない。
落ちてから借りて延命する、ができないようにしてある。
